Named Data Radio · MAC subsystem

The Blurred Name — an in-frame name filter, validated

A frame carries a lossy, blurred image of its own name. Every receiver reads that blur and decides — with no parse, no beacon, and never a dropped wanted frame — whether the frame is for it. Here is the evidence, measured on realistic NDN traffic.

Hypothesis for one subsystem — not yet integrated with time, spectrum, or multi-radio

01The safety invariant

A filter may waste work (a false positive), but it must never drop a frame the receiver wanted (a false negative). Over 8,000 deep names, every safe encoding holds FN = 0 — and the naïve "encode only the head levels" scheme fails it outright, missing 100% of genuine registrations below its cutoff. That is why the Blur keeps every level, just at lower precision, rather than truncating.

02Structure — bits per prefix

The same membership question, three data structures, matched false-positive targets. The Blur's per-name set is tiny (≈12 prefixes), and that decides it.

03Why depth is the dominant variable

Real NDN names run 8–15 components (this corpus: mean 10, modal 11). Every prefix level the sender inserts sets bits, so false positives climb with name depth and then flatten at the encoding clamp — the effect that makes shallow-name benchmarks dangerously optimistic.

04Ephemeral ID — deconfliction without beacons

The per-transmitter tag keys soft state only (RSSI, timing, dedup). Rather than a large birthday-avoidance field, nodes cooperatively deconflict: pick a free slot from overheard traffic, and rotate on a conflict hint that rides an existing data frame — no dedicated control frame ever.

05Cost, and the telemetry that measured it

The filter operations are instrumented with tracing spans. A monotonic-clock layer records per-op latency; the real ndn-observability layer publishes each span as an OTLP trace.proto message wrapped in an NDN Data packet — 10,000 spans emitted through the pipeline on the filter code itself.

06What this does not yet answer

This validates one subsystem in isolation. The MAC is a system, and these are the interactions still open — the reason this is a hypothesis, not a conclusion.

  • Shared address budget. The Blur, the Fingerprint, and the 8-bit ID together claim the 144 address bits — but slotting and named-token scheduling also key on names and may want in-frame bits. Nothing arbitrates that competition yet.
  • Profile distribution leans on a data plane we haven't specified. "Fetch the precision profile as a named object" assumes a CS / forwarding layer whose own filtering is the thing under test — a potential circularity to resolve.
  • MAC-level relay / cache / serve is asserted as capability-adaptive but unmeasured; its interaction with time-sync and the token scheduler is undesigned.
  • Realistic traffic is synthetic. Zipf roots + versioned tails match the shape of NDN names, but a real testbed trace (and real registration churn) is the honest next input.
  • On-air. Every number here is host-side simulation over a modeled corpus. The bench confirmed the mechanism at one point (#106); the swept curves are not yet on the air.
